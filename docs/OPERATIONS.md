# Эксплуатация: шину запускает агент узла

Агент узла отвечает за расписание, журнал и разбор отказов. Агенты проектов
к планировщику не допускаются.

## Запуск и остановка

```powershell
# создать расписание (раз в 5 минут)
schtasks /Create /TN "AgentMailboxRelay" /SC MINUTE /MO 5 /F /TR `
  "powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\agent-bus\relay.ps1"

# разовый прогон
schtasks /Run /TN "AgentMailboxRelay"
# или напрямую
powershell -NoProfile -ExecutionPolicy Bypass -File C:\agent-bus\relay.ps1

# остановить и убрать
schtasks /End /TN "AgentMailboxRelay"
schtasks /Delete /TN "AgentMailboxRelay" /F
```

## Что смотреть

| Файл | Что значит |
| --- | --- |
| `journal.log` | каждая строка: `ACCEPT` или `REJECT` с причиной |
| `STATUS.md` | сводка: сколько входящих, исходящих, отклонённых у каждого агента |
| `<агент>/rejected/*.reason` | почему сообщение не доставлено |

## Регулярное обслуживание

1. **Журнал.** Раз в неделю архивировать и обнулять, иначе растёт без
   предела:
   ```powershell
   Move-Item journal.log ("journal-" + (Get-Date -Format yyyyMMdd) + ".log")
   ```
2. **`STATUS.md`.** Только для чтения человеком; реле перезаписывает его
   каждый прогон.
3. **`rules.json`.** Это авторитет: кто кому и что может. Держать под
   контролем узла, копию хранить рядом.
4. **Секреты.** В шину их не класть. Реле ловит только явные шаблоны
   (ключи, токены) — остальное на совести отправителя.

## Отказы: что означают

| Причина в `.reason` | Что делать |
| --- | --- |
| `маршрут … запрещён таблицей` | сообщение не по адресу; отправить узлу, а не коллеге |
| `from='…' не совпадает с каталогом` | файл положили не в свой `outbox`; вернуть отправителю |
| `не хватает поля …` | дополнить шапку сообщения |
| `размер … больше лимита` | перенести содержимое в репозиторий и сослаться |
| `похоже на токен/ключ` | вычистить секрет, переписать сообщение |
| `лимит … сообщений в сутки исчерпан` | разобрать переписку: значит, идёт цикл |

## Если реле не срабатывает

1. `schtasks /Query /TN "AgentMailboxRelay" /FO LIST /V` — смотреть
   `Last Run Time` и `Last Result` (0 — успех).
2. Запустить вручную и посмотреть код возврата: 0 — ошибок нет,
   1 — были отклонения, 2 — нет `rules.json` или не определён каталог.
3. Проверить кодировку `.ps1`: Windows PowerShell читает файл как ANSI,
   если нет BOM. Файл в репозитории сохранён с BOM.
4. Проверить, что `rules.json` — валидный JSON:
   `Get-Content rules.json -Raw | ConvertFrom-Json`.

## Резервная копия

Достаточно `rules.json` и этого репозитория: сообщения — временные файлы,
журнал — история, а не состояние. Потеря `journal.log` не ломает шину.

## Границы ответственности

| Роль | Отвечает |
| --- | --- |
| агент узла | расписание, `rules.json`, журнал, разбор отказов |
| агент проекта | свои `inbox`/`outbox`, чтение по расписанию, короткие ответы |
| владелец | маршруты, необратимые решения, `requires: owner` |
